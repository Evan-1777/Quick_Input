## 1. 背景与目标

当前唤出快捷键固定为 `Alt+Space`（被占用时回退 `Alt+Q`），用户无法调整；管理窗口没有设置入口；界面标题栏使用通用标签图标占位，项目缺少矢量图标源文件。本次交付补齐三项能力：

- 管理窗口新增二级设置页，承载低频全局配置
- 设置页提供唤出快捷键选择，选择后立即生效并持久化，重启后沿用
- 为项目绘制 SVG 图标，并作为管理窗口的品牌标识

设计语言沿用项目既有的 Microsoft Fluent 2 令牌（`#0078d4` 品牌蓝、Segoe UI、4–8px 圆角、`surface`/`canvas`/`line` 层级），不引入新组件库或新依赖。

## 2. 阶段划分

### Phase 1：设置持久化与快捷键模型

| 项目 | 内容 |
|------|------|
| **输入** | 现有 SQLite 存储层、平台层纯函数模块 |
| **输出** | 键值设置表与读写方法；快捷键解析、校验与规范格式化模型 |
| **验收标准** | 设置可写入、覆盖、读取，未设置时返回空；快捷键解析对大小写、顺序、非法输入有确定性结果，`String()` 可往返 |

### Phase 2：平台热键热切换与绑定

| 项目 | 内容 |
|------|------|
| **输入** | Phase 1 的快捷键模型、现有 Win32 消息线程与全局热键注册、应用绑定层 |
| **输出** | 启动时按持久化值注册；运行期可切换并回滚失败注册；应用绑定层可读写快捷键设置 |
| **验收标准** | 切换注册只在消息线程执行；注册失败保留旧快捷键，写库失败回滚注册；成功后才持久化；启动回退序列有跨平台纯函数单测；Bootstrap 携带当前快捷键；本地交叉静态检查通过 |

### Phase 3：设置页与导航

| 项目 | 内容 |
|------|------|
| **输入** | Phase 2 的绑定契约、现有管理窗口与 Fluent 令牌 |
| **输出** | 管理窗口标题栏设置入口；二级设置页；快捷键单选组；失败就地提示 |
| **验收标准** | 设置页可进入、可返回；当前快捷键有明确选中态；切换成功即时反映，失败回退且展示原因；不新增依赖 |

### Phase 4：项目 SVG 图标

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 设置存储 | SQLite `settings` 键值表，与业务数据同库 | 复用既有存储层与单连接事务模型，无新增文件格式与原子写逻辑 | 独立 JSON 配置文件（双数据源、需处理并发与损坏） |
| 快捷键模型 | 平台层统一解析为「修饰键位掩码 + 虚拟键码」，以规范字符串持久化 | 存储与展示稳定，前后端只交换一种格式；解析可脱离 Windows 单测 | 前端直接传键码（浏览器键名与 VK 映射分散、难验证） |
| 快捷键选择形式 | 预设组合单选 | 结果确定、可穷举验证，避开 IME 与系统保留键的捕获边缘 | 任意按键录制（Win 键、输入法、焦点切换边界复杂，收益不足） |
| 运行期切换通道 | 向消息窗口投递自定义消息，在消息线程内重注册并回传结果 | `RegisterHotKey` 与 `WM_HOTKEY` 具有线程队列亲和性，跨线程注册会收不到触发 | 绑定 goroutine 直接注册（热键消息投递到错误线程，失效） |
| 修改失败处理 | 先注册新组合，成功后才写库；注册失败保留旧组合，写库失败回滚到旧组合 | 任一步失败都回到操作前状态，不产生「设置显示已改但热键未生效」或反向脏状态 | 先写库再注册（失败后需回滚数据库，状态同样易分裂） |
| 设置页容器 | 管理窗口内的二级子页面，保留全局标题栏 | 全局配置属 P2 低频事务，独立子视图不占用主作业画布 | 模态弹窗（配置扩展后局促）、常驻侧栏（低频入口挤占首屏） |
| 图标策略 | 矢量复刻现有 PNG 视觉语言；界面使用独立 24 视图简化标识（同源同色，非同几何） | 与 Windows 产物图标一致，且 18px 下线条不落入亚像素灰糊；无需本地栅格化工具链 | 界面直接缩放 512 视图（线条不足 1px，必然发灰）、重新导出 PNG（需额外图像链路） |
| 新增依赖 | 无 | 现有 React、Tailwind 与 Go 标准库足够 | 表单/图标/状态库（YAGNI） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 跨线程注册热键导致 `WM_HOTKEY` 投递到错误消息队列 | 🔴 高 | 统一通过消息窗口投递切换请求，注册动作只发生在消息线程；结果经缓冲 channel 回传 |
| 用户选择的新组合已被其他程序占用 | 🟡 中 | 切换失败时恢复旧注册并返回中文错误，界面就地展示，数据库不写入 |
| 注册成功但写库失败，热键与设置显示相反 | 🟡 中 | 写库失败时回滚注册到操作前组合再返回错误；回滚表达式限定在单一绑定方法内 |
| 自定义组合含 Ctrl/Shift，键入时修饰键未释放，合成出 `Ctrl+Shift+V` 等错误快捷键 | 🟡 中 | 粘贴前等待 Ctrl/Alt/Shift/Win 全部释放 |
| 启动时持久化组合被占用，回退后设置页仍显示保存值 | 🟢 低 | 回退至 `Alt+Space`、`Alt+Q` 保证可用；该极端场景记录为已知限制，不做额外状态通道 |
| 本地无法运行 Windows 产物，热键切换只能静态校验 | 🟡 中 | 注册回退序列抽为跨平台纯函数并单测，`GOOS=windows` 交叉 `vet` 覆盖编译；实机行为由用户在 Windows 验收 |
| 异步切换请求超时后消息迟到 | 🟢 低 | 结果通道带缓冲、处理端对空请求直接返回；超时仅在消息线程被占用时出现，用户重试后状态收敛，记录为已知限制 |
| 旧数据库缺少设置表 | 🟢 低 | 建表语句使用 `IF NOT EXISTS`，启动即补齐，无迁移脚本 |
| SVG 与界面标识两处维护产生漂移 | 🟢 低 | 界面标识使用独立 24 视图简化几何（两条主条 + 一条短条），与 SVG 同源同色，文档标注用途 |
| 前端手写 Wails 绑定声明与后端方法不同步 | 🟢 低 | 绑定方法、TS 接口与 `api.ts` 在同一 Task 内闭环，类型检查兜底 |

## 6. Subagent 协同规划

| 阶段 | 上下文依赖 | 并行收益 | 执行主体 | 决策理由 |
|------|-----------|---------|----------|----------|
| Phase 1：存储与模型 | 强（需对齐既有 store 与 platform 约定） | 无（后续全部依赖） | 主线 | 差分小、契约先行，主线直接推进 |
| Phase 2：平台与绑定 | 强（涉及消息线程、Wails 绑定与现有测试桩） | 暂无（强串行） | 主线 | 线程安全与回滚逻辑需主线连续推演 |
| Phase 3：设置页 | 强（依赖既有 ManagerView 结构与 Fluent 令牌） | 无（单页组件，体量小） | 主线 | 组件复用与导航状态强耦合现有代码 |
| Phase 4：图标 | 弱（仅视觉语言） | 低（单文件资产，冷启动开销大于收益） | 主线 | 交付物过小，委托无时间收益 |
| Phase 5：验证与文档 | 强（依赖全部改动与实时测试结果） | 无（串行收口） | 主线 | 需按失败结果即时修复 |

> **协同结论**：本次为单一功能纵切，链路短且阶段间强串行，全部由主线执行；不派发 Subagent，避免隔离会话重复加载上下文与契约漂移。
